Why Only One Active Gateway?

This utility is designed to communicate with Monnit gateways using the MODBUS TCP protocol on port 502.

Due to the nature of this communication, the application can only maintain one active polling connection at a time. Activating one gateway for polling ensures that all communication is clearly directed to a single device, preventing data conflicts and connection errors.

How to Enable Write-Access

The Ethernet Gateway 4 offers a local configuration page through which you can modify gateway configurations locally. The page is accessible through a web browser by visiting the gateway’s IP address. The Interface is disabled by default, so it must first be activated to access it.

Activate the HTTP Interface (local configuration page)

  • Power the gateway off.
  • Press and hold the physical Utility button on the gateway.
  • Power the gateway on by holding the Utility button down.
  • When all three LED’s illuminate and remain solid red (about 5 seconds), release the button.
  • The gateway’s HTTP Interface will be active for two minutes.
  • If you correctly activate the HTTP Interface, you can see the local configuration page when visiting the gateway’s IP address (preceded by http://) in a web browser from a computer on the same local network.

Note: Although the interface is active for two minutes, you can set that to "Always Available" in the LAN settings to keep the gateway in Write-Access.

Unlocking a Gateway

In order for a gateway to operate on a strictly local network without iMonnit, you must unlock it if it wasn’t purchased already unlocked. Gateway Unlock Codes can be purchased from Monnit sales. If your gateway is not unlocked, it must communicate with iMonnit on port 3000 to receive the unlock command.

Using an Ethernet Gateway 4 without iMonnit Online

The Gateway's Default Interface can be disabled in Gateway Settings > Default Server > Disable.

The ALTA Ethernet Gateway 4 offers Modbus TCP and SNMP Interfaces which you can poll to receive sensor data. These interfaces are disabled by default but can be enabled through iMonnit Software or the gateway’s local configuration page (HTTP Interface).

About Repeat Alerts

You can set an interval in minutes for how often an alert notification should be re-sent if a sensor's condition remains in an alert state.

  • Enter a value in minutes (1-1440).
  • The maximum value is 1440 minutes (24 hours).
  • Enter 0 to disable repeat alerts. Notifications will only be sent once when the alert is first triggered.
×

About the Default Server Interface

For the gateway to continue to receive sensor data and respond to polling on the Modbus TCP/SNMP Interface while the gateway is not sending data to Monnit Software, the Default Interface must be disabled. You may find that you’re not receiving sensor data or that your gateway stops responding to polling on the Modbus TCP/SNMP Interface intermittently if there is no connection to Monnit Software, but you haven’t disabled the Default Interface.

You will need to unlock your gateway to disable the Default Server Interface. If the gateway is not unlocked, you won’t see the option to disable this interface. If this interface is left active while operating on a private network and the gateway can’t reach a Monnit server, the gateway will continually reach out to iMonnit unsuccessfully, and the sensor network will go inactive. This will be demonstrated by sensor data not being updated in the device’s sensor registers, and the sensor LED (top LED) will go dark.

Once the gateway is unlocked, you can disable the Default Server Interface by accessing the gateway’s local configuration page (HTTP Interface) through a browser, clicking the Data Interfaces tab, and selecting Default Server Configuration, turning it off, and clicking Save Changes. When the gateway reboots, it will no longer attempt to report data to Monnit Software.
